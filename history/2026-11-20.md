**AI Builders Digest — November 20, 2026**

Agents are quietly eating the software industry from the inside. Linear just reported that more than half its tickets are now created by agents. Google is letting agents edit entire virtual worlds mid-session. And every SaaS company watching these numbers is asking the same uncomfortable question: if agents do the work, why does the customer still need your app?

---

**More than half of Linear's work is now created by agents — and that's the product, not a side effect**

Linear hit $100M ARR this year, and COO Cristina Cordova's explanation for how is worth sitting with. When Linear shipped its MCP server in May 2025, agents created 3% of the work in the product. Now it's more than half. But Cordova's warning to other SaaS companies is sharp: settling for being a database with an API on top is a strategic mistake. If the agent workflows inside your product aren't better than whatever someone could build outside it, you've already lost. So she tracks two lines obsessively: agent usage and app usage. If agent usage climbs while humans stop opening the app, that's a slow-motion death dressed up as growth.

Why it matters: Every project management, CRM, or workflow tool your company pays for is facing this same reckoning. The vendors that figure out how to make agents drive more human engagement, not replace it, will survive the transition. The ones that don't will become infrastructure with a logo.

**Google's Gemini API gets "Tool Retrieval" — giving agents access to hundreds of tools without burning through your token budget**

Google launched Tool Retrieval in preview for the Gemini API. The problem it solves: when you give an AI agent a long list of available tools, you have to include all those descriptions in every conversation, which consumes tokens and adds cost. Tool Retrieval lets agents dynamically pull only the relevant tools for a given task, keeping the context window lean.

Why it matters: This is a real infrastructure problem for anyone building agents with more than a handful of integrations. If your agent needs access to 200 possible tools but only uses 5 at a time, you've been paying for 195 you didn't need. This cuts that waste significantly, which at scale translates to meaningful cost reductions.

https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/

**OpenAI publishes a blueprint for AI-assisted security investigations**

OpenAI released a reference architecture called Daybreak Red, designed for supervised security investigations. It covers setup, safety controls, and monitoring for teams using AI to assist with offensive security work, the kind of red-teaming and vulnerability research that security professionals do before attackers do it for them.

Why it matters: AI security tooling has mostly been pitched and speculated about. A concrete reference architecture from OpenAI gives enterprise security teams something to actually evaluate, and signals that OpenAI sees regulated, supervised security use cases as a real deployment category rather than a liability to avoid.

https://openai.com/business/learn/deploying-daybreak-red

**Google Labs upgrades Project Genie: now you can edit a virtual world while you're standing inside it**

Project Genie, Google's tool for generating interactive 3D worlds from a single text prompt, now runs on Genie 4 from Google DeepMind. New features include live mid-session world editing via prompts, a conversational agent that helps build the world with you, and a gallery where users can explore and remix each other's creations. Access is currently limited to Google AI Ultra subscribers.

Why it matters: This is still early-access and niche, but the technical direction is worth noting. Real-time world editing through natural language, while inside the world, is the kind of interaction pattern that tends to migrate from creative tools into enterprise spatial computing and training simulations faster than people expect.

https://x.com/GoogleLabs/status/2123118145552749015

**Together AI ships free data caching for GPU clusters, with 20x faster warm reads**

Together AI's new Storage Accelerator is a distributed caching layer for its GPU Clusters. Warm reads come in roughly 20 times faster, each dataset is fetched from origin only once per cluster, and it requires no changes to existing applications. It's included free for Together GPU Cluster customers.

Why it matters: Training and fine-tuning runs spend a surprising amount of time waiting on data I/O, not compute. If Together's numbers hold up at real workloads, this is a quiet but meaningful cost and speed improvement for teams running repeated experiments on the same datasets.

https://www.together.ai/blog/introducing-together-storage-accelerator
